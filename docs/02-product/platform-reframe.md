# 跨平台方向重构基线

状态：`OWNER_CONFIRMED / CLOUD_SYNC_DIRECTION`

确认日期：2026-08-29（Asia/Shanghai）

## 1. 这次改变什么

Nuttie 从“仅 iOS、本地无账号”调整为一个跨平台产品：

- 客户端统一采用 Expo + React Native，首批覆盖 iOS、Android 和 React Native Web；
- 主营网页形态是手机尺寸的 H5，同时保留平板、横屏和大屏浏览器的完整工作流；
- 用户可以注册、登录，并在多台设备之间同步自己的记录；
- 每个客户端仍保留本地缓存与离线写入队列，网络恢复后再进行可观测的同步；
- 服务端使用 PostgreSQL 保存同步权威数据，部署拓扑参考 `D:\github\Royal-Flush`，但首期只保留 web、api、postgres 三个必要服务。

## 2. 被替代与被保留的约束

### 被替代

- “不建设业务服务器、账号、远程数据库”的旧约束；
- “iOS 17+ 是唯一正式平台”的旧范围；
- “所有业务数据永远只在设备本地”的旧叙述。

### 被保留

- 非医疗产品边界和非诊断文案；
- AI 仅由用户主动触发、可取消、候选确认后保存；
- API key、数据库密钥和原始 AI 载荷不进入同步数据；
- 营养七字段、来源、单位、估算与缺失值语义；
- 本地导出、删除和数据访问需要可解释、可恢复、fail-closed；
- 不引入广告、行为分析、远程 Push 或付费墙作为首期依赖。

## 3. 首个可交付纵向切片

首期不试图一次实现 F01-F24 全部能力，而是打通一条真实跨端路径：

1. 邮箱和密码注册/登录；
2. 今日首页：能量摘要、宏量摘要、饮水、体重和最近记录；
3. 手工新增一条餐食、饮水或体重记录；
4. 记录进入本地队列并同步到 PostgreSQL；
5. 在另一浏览器/设备登录后看到同一份记录；
6. 网络暂时不可用时仍能新增，恢复后显示同步状态；
7. 趋势页在手机、平板和桌面上维持相同信息架构但改变布局密度。

其余 AI、食品包、提醒、导入导出、平台健康数据和原生能力按后续增量交付，并继续使用现有 harness 作为领域回归依据。

## 4. 迁移规则

旧 `docs/`、`prototypes/` 和 `tools/` 是研究、决策和领域行为资产，不因重构删除。新的正式工程必须：

- 复用已确认的领域命名与营养字段；
- 在代码和 API 合同中显式标注 `source`, `revision`, `syncStatus`；
- 把原型中“只更新页面内存”的行为替换为真实客户端缓存/队列；
- 为每一个尚未迁移的能力保留状态，而不是把占位实现描述成已完成。

## 5. 交付门槛

每个重构部分都必须是一个可独立回滚的原子提交，并在提交后 push 到工作分支。生产部署仍需经过 CI、人工验收和受保护分支，不因本次持续 push 自动发布。
