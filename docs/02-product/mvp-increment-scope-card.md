# 首个 MVP 增量与后续范围边界决策卡

| 字段 | 内容 |
| --- | --- |
| 工件 ID | `MVP-INCREMENT-SCOPE-CARD-001` |
| 状态 | `INTERNAL_CANDIDATE / OWNER_REVIEW_REQUIRED / IMPLEMENTATION_NOT_AUTHORIZED` |
| 对应门禁 | `G2 产品基线` |
| 决策问题 | 首个可实现 MVP 增量采用哪一条范围边界？ |
| 当前选择 | `NONE`；推荐 A 不等于 Owner 已选择 |

## 1. 为什么现在需要这张卡

F01–F24、REQ-F01–REQ-F24 和 AT-F01–AT-F24 已覆盖完整产品范围，W1–W4 也已经给出依赖顺序；当前 G2 缺的不是功能清单，而是首个实现增量与后续范围之间的明确切片。

这张卡只决定第一刀交付边界。它不删除 D-017 已保留的完整范围，不接受任何仍为候选的产品或技术决定，也不授权正式 React Native 根工程、Prebuild、原生 iOS、签名、真机或发布工作。

## 2. 所有选项共享的不变量

1. F01–F24 的总范围和“实现 / 本地重构 / 延后决定 / 明确移除”处置保持不变。
2. 首个增量只面向 D-048 已接受的 iPhone 竖屏，并保持简体中文、iOS 17+、本地优先、无业务服务器。
3. 本地食品、记录、查询和保存不得依赖第三方 AI、账号、遥测、CloudKit、远程配置或业务网络。
4. D-052 未关闭不阻断 Owner 本机、不含 USDA 再分发的本地路径；任何 USDA 境外分发继续失败关闭。
5. D-053 未关闭时不读取 AI key、不组装敏感正文、不创建 transport、不发送；AI 保留在后续范围不等于删除 F01/F02/F16。
6. SQLCipher/Keychain、来源与缺失值、确认前零业务写入、成功恰好一次写入、删除与迁移安全边界不因切片缩小而降低。
7. 所有后续实现仍须逐增量满足产品、设计、架构、安全和 QA 门禁；本卡的 Owner 选择本身不构成 PX-5、G4 或正式实现授权。

## 3. 互斥选项

### A. 本地餐食纵向闭环（推荐）

首个增量 ID：`MVP-I1-LOCAL-MEAL`

包含：

- D-038 已接受的四目的地导航外壳，以及未进入本增量目的地的真实、不可误操作状态；
- D-039 的 `D039-I1-LOCAL`：添加餐食壳、本地搜索、最近使用、创建用户食品、统一检查与保存；
- 当前日期与餐次上下文中的餐食查看、更正和删除；
- D-013 七项营养快照、单位、来源、缺失值与估算状态；
- 对本增量源码、依赖、配置和运行证据执行 F20/F23/F24 的无 IAP、无广告/遥测、无定位失败关闭审计。

明确留到后续：

- 条码、相机和系统媒体路径进入 `D039-I2-SCAN`；
- AI 图片、文字和参考草稿进入 `D039-I3-AI` / W3；
- 目标公式、健康评分、完整趋势、体重、运动、饮水、提醒、备份恢复等进入后续手工闭环增量；
- HealthKit、步数及其他系统集成保持 W4。

主要理由：这是能够同时验证本地数据、来源、事务、纠错和核心日记价值的最小纵向切片；它不以 D-052/D-053 为前置，也不把未获批准的公式、健康规则、Provider 或原生媒体能力塞入第一刀。

已知门禁：D039-PX5-B03（D-045 最近使用政策）、D039-PX5-B06（正式工程与增量授权）、正式数据 adapter，以及 D039 B01/B02 对应的实现自动化仍须关闭；本卡不改变这些状态。

### B. 完整手工本地 MVP

首个增量 ID：`MVP-I1-FULL-MANUAL`

把 W1 本地数据与隐私地基、W2 完整手工本地闭环合并为一个首增量，覆盖 F03–F15 的非 AI 路径及 F17–F24 的本地替代、数据权利和禁止能力边界；AI 与 HealthKit 仍后置。

优点是首个验收点更接近完整日常使用；代价是同时引入食品数据包、公式、目标、趋势、提醒、备份、更多 Owner 规则和更大的原生/数据测试矩阵，首个 G5 反馈明显更晚。

### C. 本地餐食闭环加离线条码

首个增量 ID：`MVP-I1-LOCAL-MEAL-BARCODE`

在 A 的基础上加入 `D039-I2-SCAN`、本地精确 GTIN 查询、未命中手工建档、相机拒绝/受限/撤权和系统媒体降级；AI、公式、完整趋势及系统集成继续后置。

优点是首个增量同时覆盖手工与包装食品录入；代价是首刀必须等待 D039-PX5-B04、D039-PX5-B07、食品数据包许可/schema/签名和相机真机证据，不再是纯本地数据层的最短反馈路径。

### Other

Owner 可提出另一条边界，但必须同时列出稳定增量 ID、包含项、明确后置项、依赖、验收 ID 和不变量影响；不能只写“先做简单的”或用切片删除 F01–F24 总范围。

## 4. 选项比较

| 维度 | A 本地餐食纵向闭环 | B 完整手工本地 MVP | C 本地餐食 + 离线条码 |
| --- | --- | --- | --- |
| 首次可验收范围 | 最小纵向价值闭环 | 最大手工使用闭环 | 纵向闭环 + 原生扫描 |
| 第三方 AI 前置 | 无 | 无 | 无 |
| USDA 境外再分发前置 | 无；可用用户自建和获准本地数据 | 取决于纳入的数据包 | 无；但条码包本身须许可/签名可审 |
| 原生相机前置 | 无 | 视完整 W2 具体路径而定 | 有 |
| 公式/健康规则前置 | 无 | 有 | 无 |
| 当前关键阻断 | B03、B06、数据 adapter | W1/W2 的全部未决规则与工程门禁 | B03、B04、B06、B07、数据包与真机 |
| 建议 | 推荐 | 不推荐作为第一刀 | 仅在原生与数据证据可快速取得时考虑 |

## 5. 选择后的记录与门禁动作

Owner 选择后，PM 必须：

1. 记录原始回复、选项键、日期和明确未授权边界；
2. 将选择写入权威决定台账及机器可读副本，并保持两者一致；
3. 更新 G2、需求分期、验收追踪和当前交接中的首增量/后续范围；
4. 为所选增量形成独立 DoR，逐项引用需求、验收、依赖和证据；
5. 只有相关阻断全部关闭且出现单独的正式工程与实现授权后，才允许开始正式实现。

在上述动作完成前：

```text
ownerChoiceRecorded: false
mvpIncrementScopeFrozen: false
g2Passed: false
formalRootProjectAuthorized: false
nativeIosWorkAuthorized: false
formalImplementationAuthorized: false
```
