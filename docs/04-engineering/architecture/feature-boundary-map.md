## 2. 跨功能不变量

1. `PURE_LOCAL` 和 `LOCAL_REPLACEMENT` 路径必须通过飞行模式验收。
2. AITransport 不得直接写业务库；AI 响应按不可信输入处理。
3. 所有导入先进入 staging 并完整验证；文件/DB 跨域切换使用 durable intent、不可变 final/generation 与启动对账，保证 crash consistency，不能宣称全局原子事务。
4. “删除全部数据”移除 pending/delivered 本地通知、关闭连接，并递归清除 DB/WAL/SHM、媒体、缩略图/AI 输入普通缓存、URL cache/cookie、明文 staging、App Group、业务配置、日志和 Keychain；外部 Files 备份、系统/用户截图及其他 App 副本不在 App 控制内。
5. iOS 权限在功能触发点申请，拒绝后保留手动路径或清晰未安排状态。
6. 产品分期不能删除 D-017 的公开对标范围，但 `EVIDENCE_GAP` 不能被阶段计划升级为已证实功能。
7. F09 的能力存在性与算法证据必须分开：界面能力已由官方截图直接支持，规则/来源仍待 Owner；F03 条码结果字段则没有当前截图直接证据。

## 3. 九组公开证据缺口

以下内容只能进入机会/验证清单，不能成为确定系统契约：

1. 引导流程、目标算法，以及 F09 评分/风险/益处的规则与生成来源；F09 能力本身不是可删除缺口。
2. 食物库高级操作。
3. AI 纠错、额度和付费边界。
4. 条码覆盖率与 OCR 细节。
5. 饮水、运动、步数和 HealthKit 语义。
6. 提醒规则和统计细则。
7. 备份、导出和同步语义；Nuttie 的本地闭环是自身设计，不是竞品事实。
8. 游客、订阅和广告边界。
9. Widget、Live Activity 等平台扩展能力。

## 4. PRD 防误承诺检查

架构评审 PRD 时必须拒绝以下表述：

- “AI 可离线使用”或“AI 失败会自动保存识别结果”。
- “扫描任意中国商品都能找到完整营养”。
- “官方截图已证实条码结果页包含某些具体字段”。
- “健康评分算法未知，所以不实现或移除 F09 评分、微量标签、风险与益处”；准确边界是能力保留分期、规则与生成方式待 Owner。
- “通知一定按时响起”。
- “首版自动同步 HealthKit”。
- “本地档案等同竞品账号/会员/云同步”。
- “备份永远不会进入云端”；准确表述是“Nuttie 不主动上传，最终 Files 位置由用户选择”。
- 将 cross-source、policy-only 或 pending evidence 写成 iOS 已确认行为。
