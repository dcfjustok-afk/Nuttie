# 近七日摄入/消耗事实读模型

> 状态：`SPIKE / FRAMEWORK_AGNOSTIC / NON_PRODUCTION`
>
> 对应能力：F11、REQ-F11、AT-F11；对应旅程：J-07 本地趋势分支

## 1. 目的与结论

`tools/seven-day-energy-trend-harness.mjs` 把近七个本地日历日的摄入和消耗建模为只读、可追溯的本地事实窗口。它只消费 Repository 已经提交的事实，不计算新的消耗、目标或健康结论。

合同固定以下不变量：

- 查询范围只能是以显式 `endLocalDate` 结尾的连续七个本地日历日；跨月、跨年和闰日均有稳定结果；
- 摄入与消耗是两条独立流；摄入只引用餐食记录，消耗只引用手工记录或明确标记的本地估算；
- 每条事实保留原始 kcal/kJ 字符串、单位、来源记录 ID、revision 和质量标签；
- kJ 使用 `125/523 kcal` 的精确有理数换算，聚合不引入浮点舍入；
- 没有事实的日期为 `MISSING`，显式 0 为 `KNOWN`，二者不得混淆；
- 七日文字语义摘要同时给出日期范围、known/missing 天数、缺失日期与已知总量；不计算平均值；
- Repository 快照必须完整、查询一致、指纹正确且只包含窗口内事实，修订或删除后的新快照会重新计算，不复用旧缓存。

该夹具不是图表 UI、SQLite 查询、健康算法或正式 App 实现，也不构成 G4 PASS。

## 2. 来源语义

| 流 | 允许来源 | 质量边界 |
| --- | --- | --- |
| `INTAKE` | `MEAL_RECORD` | 保留 `SOURCE_REPORTED` 或 `USER_ENTERED` 等既有事实标签 |
| `BURNED` | `MANUAL_BURN` | 必须标为 `USER_ENTERED` |
| `BURNED` | `LOCAL_ESTIMATE` | 必须标为 `ESTIMATED`，不能冒充测量值 |

首版不出现 HealthKit、自动步数或测量值占位。合同不定义如何从运动时长、体重或其他字段推导消耗；这些公式仍待批准。

## 3. 完整性与展示边界

`semanticSummary` 是图表的结构化文字等价信息，供后续组件和无障碍实现消费：

- `COMPLETE`：七日都有该流的事实；
- `PARTIAL`：至少一日已知且至少一日缺失；
- `MISSING`：七日全部缺失；
- `knownTotalExactKcal` 只合计已知事实，并与缺失天数同时出现，不能被解释为完整周期总量。

4096 条事实限制只是单个七日快照的防滥用资源预算，不是用户记录上限、产品规格或医学阈值。

