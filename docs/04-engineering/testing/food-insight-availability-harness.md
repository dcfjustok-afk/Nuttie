# F09 营养事实与洞察可用性合同

状态：`SPIKE / FRAMEWORK_AGNOSTIC / NON_PRODUCTION`

路径：`tools/food-insight-availability-harness.mjs` 与 `tools/food-insight-availability-harness.test.mjs`

## 目的

F09 同时包含两种成熟度不同的内容：D-013 已批准、由本地来源提供的七项营养事实，以及公开截图已证明能力存在但规则/来源未知的健康评分、微量营养标签、风险和益处。本合同把两者严格分层，防止“未知算法所以删除能力”和“能力已证实所以伪造内容”两种越界。

## 已覆盖边界

- 只接受经过现有营养快照完整性检查的本地事实；数据包快照必须保留 verified catalog 身份，序列化后必须由原目录 trust context 重新绑定。
- 能量、蛋白质、碳水化合物、脂肪、纤维、糖和钠七项按原状态与标准单位形成只读展示证据。
- `MISSING` 保持“缺失而不是零”，`TRACE/USER_ENTERED_TRACE` 保持“微量但无数值”，`ESTIMATED` 保持来源估算，不得冒充测量值。
- `FOOD-04~07` 对应的健康评分、微量营养标签、风险和益处能力均固定为 `PRESERVED_FOR_PHASED_DELIVERY`，证明它们没有被范围裁掉。
- 四类高级能力的内容固定为 `NOT_AUTHORIZED / NONE`；请求无法注入分数、微量字段、风险/益处文本或 Owner 授权位。
- 完整结果用确定性指纹绑定；修改营养事实、来源、能力清单、阻断项、边界或派生展示证据都会拒绝。

## 明确不授权

本工件不选择或实现健康评分算法、阈值、输入范围和适用人群；不批准微量字段全集、数值来源或阈值；不批准风险/益处的本地规则、AI 生成方式、医学依据、免责声明或个体化范围。它不读取用户档案，不计算诊断/推荐，不产生 AI 请求、业务 effect、持久化、文件、网络、时钟或原生调用，也不创建 UI 或正式工程。

“能力保留”只说明 D-017 的范围没有被删除，不表示内容已经可以展示。只有相应规则、来源、安全边界和 Owner 决定全部形成新合同后，才能新增非空内容状态。
