# ADR-0005：签名离线数据包与手动加密备份

- 状态：accepted
- 日期：2026-07-31
- 关联决策：D-002、D-006、D-012、D-013
- 决策者：Owner

## 上下文

Nuttie 不提供业务服务器或数据同步，但需要可更新的营养数据和可迁移的用户数据。直接在线查询食物库违反本地边界；直接复制活跃 SQLite 文件容易受 WAL、schema 和版本差异影响；未签名的数据包会形成供应链入口。

## 决策

1. 首发基础数据来自台湾食药署、USDA Foundation/SR 和用户自建记录。
2. 预置数据随 App 发版；额外更新只通过用户从 Files 选择的签名数据包。
3. 数据包含版本、兼容性、来源、许可、文件哈希和 detached signature；验证通过后在 staging 中构建，再通过不可变 final、durable intent、SQLCipher ref 事务和启动对账激活。
4. 七项核心营养为能量、蛋白质、碳水、脂肪、纤维、糖和钠，并保留原值、原单位、来源及缺失/trace 语义。
5. 用户迁移使用手动、版本化、认证加密的完整备份；默认排除 iCloud，不自动上传。
6. 恢复在独立 staging 完成认证、校验和全部迁移，以目标设备密钥构建完整 generation，再通过 durable intent、active pointer 和启动对账完成或回滚；替换/合并和恢复点策略由 D-030 决定。

## 后果

- App 在无网络环境仍可安装、查询和更新用户选择的数据包。
- 数据新鲜度受 App 发版或手动导入频率限制，这是本地优先的明确代价。
- 不同许可证的数据需隔离，许可和署名是运行数据的一部分。
- 具体数据包签名算法和备份 KDF/envelope 实现仍需 D-026、D-027 确认。
- 备份恢复采用替换还是合并、是否建立恢复点仍需 D-030 确认。
- D-006 未批准额外明文 JSON/CSV 导出；是否提供由 D-035 决定。
- 文件 rename、SQLite transaction、Keychain 与 active pointer 不构成全局原子事务；协议只承诺启动对账后的 crash consistency。
- Files 的最终保存位置由用户选择；选择 iCloud/第三方位置后不再是物理纯本地。

## 验证

- 篡改签名/哈希、错误许可、版本不兼容、路径穿越、ZIP bomb 和空间不足全部拒绝，旧数据保持不变。
- 导入每个持久化点中断后，对账得到完整旧版或完整新版且清理 orphan。
- 备份错误口令、损坏和迁移失败不改变 active generation；恢复提交中断后确定性完成或回滚。
- 完整备份往返保持稳定 ID、来源、七项营养、时间和媒体哈希。
- 飞行模式覆盖数据包导入、查询、备份和恢复。

## 复审条件

若未来增加在线数据更新、iCloud 自动同步或账号恢复，必须新建决策并重新评估许可、隐私、冲突合并和服务器成本。
