# 状态、简中文案与无障碍基线

状态：`DRAFT_FOR_REVIEW`  
范围：所有首版用户旅程；不锁定配色、字体、组件库或视觉风格。

## 1. 状态设计总则

1. 状态必须回答三件事：发生了什么、现有数据是否安全、下一步能做什么。
2. 局部失败留在局部。AI 无网络不应遮挡本地日记；通知拒绝不应阻断记录。
3. 有草稿的失败先保草稿，再提示恢复动作；不得让“重试”成为唯一出口。
4. 用图标、文字和可访问状态共同表达，不能只靠颜色。
5. 加载状态预留稳定空间；动态内容不得推移主要操作或与其他内容重叠。
6. 不展示虚假精度。AI 估算、公式估算、用户值、数据包值和缺失值均有来源标签。

## 2. 应用级状态

| State ID | 条件 | 用户可见行为 | 允许动作 | 禁止动作 |
| --- | --- | --- | --- | --- |
| ST-APP-01 `booting` | 正在打开本地安全存储 | 稳定的启动状态，不显示网络加载 | 等待；系统取消时退出 | 发网络请求、索取权限 |
| ST-APP-02 `firstRun` | 无本地档案且数据库正常 | 提供本地开始或恢复备份 | 开始设置、恢复 | 强制注册、强制 AI 配置 |
| ST-APP-03 `readyLocal` | 数据库可读写 | 所有本地能力可用 | 正常操作 | 无 |
| ST-APP-04 `dbKeyUnavailable` | Keychain 密钥不存在或不可读 | 说明本地数据暂时无法打开 | 重试、恢复备份、查看错误代码 | 自动新建覆盖旧库 |
| ST-APP-05 `migrationFailed` | 数据库升级事务失败 | 进入恢复模式，说明原数据未被确认迁移 | 重试、恢复、导出非敏感诊断 | 继续业务写入 |
| ST-APP-06 `readOnlyRecovery` | 数据可读但安全写入条件不成立 | 明确“仅查看/恢复”状态 | 查看可恢复信息、备份/恢复（若技术上可行） | 编辑、删除、AI 入库 |
| ST-APP-07 `storageLow` | 操作所需空间不足 | 显示所需空间和受影响操作 | 清理候选、取消 | 半完成导入或备份 |

应用不维护“全局在线/离线”作为核心可用性状态，因为唯一允许联网的是 `AITransport`。网络状态只在用户进入 AI 任务后出现。

## 3. AI 状态机

下列状态机按 `UXD-13` 推荐项 A 展示统一的逐次预览。D-014 已接受的强制范围是营养标签照片；若 Owner 选择 B 或 C，其他 AI 输入可在当前任务页完成同等明确的发送动作，但仍禁止后台或隐式发送。

```text
localInput
  -> providerPolicyCheck
  -> sendPreview
  -> userConfirmed
  -> sending
  -> parsedCandidate
  -> userReview
  -> committedLocal

sendPreview -> preSendCancelled
providerPolicyCheck -> providerPolicyBlocked
sending -> inFlightCancelled | timeout | authFailed | rateLimited | invalidResponse
任一失败 -> localInput（草稿保留）或 manualReview
```

| State ID | 必须显示 | 主动作 | 次动作 | 写入业务库 |
| --- | --- | --- | --- | --- |
| ST-AI-01 `unconfigured` | AI 未配置；本地能力仍可用 | 配置 AI | 改用手工录入 | 否 |
| ST-AI-02 `invalidHttps` | 仅支持 HTTPS；指出需修改的字段 | 修改地址 | 取消 | 否 |
| ST-AI-03 `keyUnavailable` | 无法读取 API 凭据，不回显旧 key | 重新输入 key | 手工录入 | 否 |
| ST-AI-04 `sendPreview` | 输入预览、数据类型、目标 host、model、首次说明状态 | 确认发送 | 返回修改/取消 | 否 |
| ST-AI-05 `sending` | 正在发送/处理、目标 host、取消入口 | 取消 | 无 | 否 |
| ST-AI-06 `candidateReview` | 每项候选、来源为 AI、缺失和校验警告 | 检查后保存 | 编辑、删除候选、放弃 | 仅用户保存时 |
| ST-AI-07 `offlineOrTimeout` | 未收到响应；本地草稿已保留 | 重试 | 手工录入 | 否 |
| ST-AI-08 `authFailed` | 地址/model/key 可能不匹配；不展示敏感响应 | 检查配置 | 手工录入 | 否 |
| ST-AI-09 `rateLimited` | 服务暂时限制请求 | 稍后重试 | 手工录入 | 否 |
| ST-AI-10 `invalidResponse` | 返回内容无法安全解析 | 手工录入 | 重试/查看非敏感摘要 | 否 |
| ST-AI-11 `preSendCancelled` | 未发送；输入草稿仍在设备内 | 继续编辑 | 退出 | 否；未创建网络请求 |
| ST-AI-12 `inFlightCancelled` | 已停止等待；内容可能已到达 AI 服务，无法从本机撤回 | 继续编辑 | 退出 | 否；终止或忽略本地响应，不生成候选 |
| ST-AI-13 `committedLocal` | 已保存到指定日期和餐次 | 查看日记 | 继续添加 | 是，保存确认后的结构化数据 |
| ST-AI-14 `providerPolicyBlocked` | 实际 Provider、载荷类别、policy 证据版本和 `DENY/UNKNOWN/EXPIRED` 原因；D-053 未接受时明确“尚未准入” | 返回修改 | 手工录入、查看本地配置 | 否；不读取 key、不生成 Authorization/请求体 |

### 3.1 每次发送预览的最小内容

- 照片缩略图或将发送的完整文本。
- 数据类别，例如“餐食照片”“营养标签照片”“所选 7 天饮食汇总”。
- 实际目标 host 与 model；不显示完整请求路径中的敏感查询参数。
- 本地 Provider policy 的证据版本、核验/到期状态；非 `ALLOW` 时只显示阻断状态，不出现“确认发送”。
- 是否已移除 EXIF，以及不会自动附带哪些数据。
- 明确的“确认发送”和“返回修改”。关闭预览等同取消，不能默认同意。
- 发送后的“取消”只代表停止本地等待或处理；界面不得暗示已从 Provider 撤回或删除载荷。

## 4. 权限状态

| 权限 | 首次触发点 | 未决定时 | 拒绝/受限时 | 已授权后 |
| --- | --- | --- | --- | --- |
| 相机 | 扫描条码或拍照 | 先给任务相关说明，再调用系统请求 | 输入条码、搜索、手工录入、相册（若可用）、系统设置 | 回到原任务，不跳到其他首页 |
| 相册 | 用户选择已有图片 | 先请求用户选择，不申请无关的全库访问 | 拍照、文字或手工录入、系统设置 | 处理用户明确选择的媒体 |
| 通知 | 用户保存第一条需要通知的规则 | 解释本地通知及系统限制后请求 | 规则保留为未安排，系统设置入口 | 显示 App 内规则和系统授权状态 |
| HealthKit | 首版不触发 | 不展示请求 | 不适用 | 第二阶段另行设计 |
| Face ID | 未由 D-015 选择 | 不展示请求 | 不适用 | 只有新增 Owner 决策后设计 |
| 定位 | 不需要 | 不请求 | 不适用 | 不适用 |

权限文案只解释当前任务，不承诺权限会提高 AI 准确率，也不使用“为了更好地服务你”之类宽泛理由。

## 5. 空态

空态不是错误，也不放置无法执行的入口。

| Empty ID | 条件 | 标题候选 | 主动作 | 补充边界 |
| --- | --- | --- | --- | --- |
| ST-EMPTY-01 | 当天没有餐食 | 还没有餐食记录 | 添加餐食 | 不评价用户是否“自律” |
| ST-EMPTY-02 | 没有设置目标 | 尚未设置每日目标 | 设置目标 | 日记仍可记录 |
| ST-EMPTY-03 | 没有体重记录 | 还没有体重记录 | 记录体重 | 不自动要求 HealthKit |
| ST-EMPTY-04 | 趋势样本不足 | 记录几次后可查看趋势 | 添加记录 | 不绘制误导性的零线 |
| ST-EMPTY-05 | 本地搜索无结果 | 本地食物库未找到 | 创建用户食品 | 可选 AI 不能成为唯一动作 |
| ST-EMPTY-06 | 条码未命中 | 本地食物库未找到该条码 | 创建食品 | 辅助动作：输入标签、用户主动 AI |
| ST-EMPTY-07 | 未配置 AI | 尚未配置 AI | 配置 AI | 辅助动作：继续手工录入 |
| ST-EMPTY-08 | 没有提醒 | 还没有提醒 | 新建提醒 | 不启动即请求通知权限 |
| ST-EMPTY-09 | 没有备份历史 | 本机没有备份记录 | 导出加密备份 | 不声称 Files 中不存在其他备份 |
| ST-EMPTY-10 | 没有用户食品 | 还没有自建食品 | 创建食品 | 数据包食品与用户食品分区 |

标题和按钮是内容候选，须在原型可用性审查后定稿。

D-039 已冻结添加餐食首层的状态落点：`ST-EMPTY-05`、`ST-EMPTY-06`、`ST-EMPTY-07` 分别属于本地搜索、扫描和 AI 分支；任何空态或拒绝态都必须保留本地搜索或创建食品路径，不能把 AI 变成唯一恢复动作。完整顺序见 [D-039 PX-4 设计基线](d039-px4-design-baseline.md)。

## 6. 错误与恢复矩阵

| Error ID | 场景 | 核心文案结构 | 恢复动作 | 保持不变的数据 |
| --- | --- | --- | --- | --- |
| ST-ERR-01 | 本地保存失败 | “没有保存。你填写的内容仍在。” + 非敏感原因 | 重试、返回修改 | 当前草稿、原日记 |
| ST-ERR-02 | 条码无法识别 | “没有识别到完整条码。” | 重扫、输入数字、手工搜索 | 已选日期与餐次 |
| ST-ERR-03 | 数据包签名/哈希失败 | “无法验证数据包，未进行导入。” | 选择其他文件、查看来源要求 | 当前数据包、历史日记 |
| ST-ERR-04 | 数据包许可缺失 | “数据包缺少必要的来源或许可信息。” | 查看要求、取消 | 当前数据包 |
| ST-ERR-05 | 数据包版本不兼容 | “此数据包需要不同版本的 Nuttie。” | 更新 App（由 TestFlight 流程处理）、取消 | 当前数据包 |
| ST-ERR-06 | 备份口令错误 | “无法解密备份。现有数据没有变化。” | 重新输入、选择其他文件 | 当前数据库和 Keychain |
| ST-ERR-07 | 备份损坏/媒体缺失 | “备份未通过完整性检查，未进行恢复。” | 查看缺失摘要、选择其他文件 | 当前数据库 |
| ST-ERR-08 | 空间不足 | “需要 X，当前可用 Y。” | 管理本地存储、取消 | 当前数据库/数据包 |
| ST-ERR-09 | 数据库解锁失败 | “无法打开本地加密数据。” | 重试、从备份恢复 | 原数据库文件 |
| ST-ERR-10 | 数据库迁移失败 | “升级未完成，已停止写入。” | 重试、恢复、查看错误代码 | 事务前数据 |
| ST-ERR-11 | 通知未授权/被撤销 | “这些提醒目前不会由系统显示。” | 打开系统设置 | 提醒规则、业务记录 |
| ST-ERR-12 | TestFlight 构建失效 | 由 iOS/TestFlight 主导；项目文档说明安装新的有效构建 | 打开 TestFlight 获取可用构建 | App 内不承诺可绕过 Apple 限制 |

高风险失败必须支持选择和朗读错误摘要；错误码应稳定、可供朋友反馈，但不得包含 key、完整路径、原始 AI 内容或健康记录。

## 7. 简体中文内容原则

### 7.1 品牌与语气

- 产品名：`栗子自律`；英文名：`Nuttie`。
- 中文标语：`积“栗”前行，“立”见更好的自己。`
- 英文标语：`Small steps, solid growth.`
- 品牌双关只用于品牌时刻，不在每个完成、错误或健康提醒中重复。
- 语气平静、具体、非评判。描述记录和趋势，不给用户贴“自律/不自律”的标签。

### 7.2 术语基线

| 概念 | 首选表达 | 避免 |
| --- | --- | --- |
| energy | 能量；数值单位写“千卡” | 卡路里/大卡混用而不解释 |
| protein/carbohydrate/fat | 蛋白质、碳水化合物、脂肪；紧凑位置可在首次解释后用“蛋白质/碳水/脂肪” | P/C/F 直接面向普通用户 |
| AI output | AI 估算、AI 生成、供参考 | 准确识别、健康诊断、最佳方案 |
| missing | 未提供、未检测、低于检出限、微量，按源数据分别显示 | 一律显示 0 |
| local | 存在此设备上的 Nuttie 中 | 绝对安全、永不在云端（Files 位置不受 App 控制） |
| backup | 加密备份 | 云同步、自动备份 |
| failure | 未完成、没有保存、无法验证 | 操作失败（不说明结果）、你输入错误 |

### 7.3 行动文案

- 按钮用动词加对象：`添加餐食`、`记录体重`、`确认发送`、`导出加密备份`。
- 危险操作写明对象：`删除全部本地数据`，不使用模糊的 `确认`。
- 关闭或返回 AI 发送预览不得标成同意；默认焦点不落在危险动作。
- 不在紧凑按钮中放长句；必要说明放在邻近正文并可由 VoiceOver 关联。

### 7.4 日期、数字与单位

- 首发使用简体中文日期格式并明确年份，跨年历史不只显示月/日。
- 数值精度由领域规则统一；列表与详情保持一致，输入原值不因展示舍入丢失。
- 每个营养值同时具备数值、单位和基准（每 100 g、每份或实际份量）。
- 图表区间、缺失天数和单位必须在屏幕与 VoiceOver 摘要中都可获取。

### 7.5 健康与 AI 风险文案

- 健康评分属于 F09 完整对标范围，但在展示前必须有公开规则、适用范围和 Owner 决策；在此之前不展示虚构分数或占位。
- 风险、益处、饮食方案和食谱统一标明生成来源与时间，并使用“可能”“估算”“供参考”。
- 对特殊人群使用明确转介：相关内容不能替代医生或注册营养专业人员的建议。
- 不通过红色、警报声或羞辱性文案夸大单次记录。

## 8. 无障碍基线

| 领域 | 基线要求 | 验收重点 |
| --- | --- | --- |
| Dynamic Type | 支持系统动态字体；文本可换行，不能用视口宽度缩放字号 | 最大无障碍字号下无裁切、遮挡或关键操作丢失 |
| VoiceOver | 所有控件有名称、角色、状态；相关值组成可理解顺序 | 餐次、营养、AI 发送预览、危险确认可完整操作 |
| 触控目标 | 交互目标至少 44 x 44 pt，图标按钮有可访问名称和可见焦点/按压反馈 | 日期切换、增删、图表点、扫描控制不误触 |
| 对比度 | 普通文本至少 4.5:1；大文本至少 3:1；状态不用颜色单独区分 | 浅色/深色模式及错误、缺失、AI 来源标识 |
| 减弱动态效果 | 尊重 Reduce Motion；状态改变不依赖大幅位移或循环动画 | AI 处理、图表切换、保存反馈 |
| 图表 | 提供标题、时间范围、单位、文字摘要和数据表/逐点访问 | VoiceOver 能读出趋势与缺失日期，不只读“图表” |
| 表单 | 标签持久可见；错误与字段关联；键盘类型适合数值但不阻挡粘贴 | 营养、份量、Base URL、model、备份口令 |
| 权限与错误 | 系统拒绝后焦点回到解释与替代动作；错误公布但不反复打断 | 相机、相册、通知、数据库恢复 |
| 认知负担 | 一屏只保留一个明确主动作；专业术语就地解释 | AI 配置和备份恢复不要求用户记忆上一屏信息 |
| 触觉/声音 | 仅作辅助反馈，遵守系统设置，不能代替文字和状态 | 扫码成功、保存、错误 |

D-039 的 `D039-ENTRY` 读序固定为标题/上下文 → 本地搜索 → 最近使用或其空态 → 同级扫描与 AI → 创建用户食品；返回时优先恢复原触发控件。该顺序是设计基线，不等于 VoiceOver 真机证据。

## 9. 响应式与稳定布局约束

- 先覆盖 iPhone 小屏宽度与横向安全区；iPad 不是 D-011 自动承诺的首版目标。
- 日期条、营养计数、图表和扫描框使用稳定尺寸或明确约束，加载、错误和长文本不能改变整个页面结构。
- 简中最长词和较长食品名允许换行；关键数值与单位不互相覆盖。
- 键盘弹出、系统权限返回、Files 选择器返回和动态字体增大后，主动作仍可到达。
