## 2. J-01 首次启动或从备份恢复

**目标**：不注册、不联网、不批量请求权限即可进入可用状态。

正常路径：

1. 启动 → 校验本地数据库状态。
2. [无现有数据] 显示品牌、简短本地数据说明、非医疗边界，以及“开始设置”“从加密备份恢复”。不使用功能导览轮播。
3. “开始设置” → 填写完成本地目标所需的最小资料；非必要字段允许稍后补充。
4. 显示目标预览和数据来源说明 → 用户确认后创建本地档案和目标方案。
5. 进入当日日记；此时没有相机、相册、通知或 HealthKit 权限请求。

分支与失败：

- 用户暂不填写：允许进入日记，但目标相关位置显示“尚未设置目标”，不伪造推荐值。
- 选择恢复：转 J-11；恢复取消或失败后仍可回到本地新建路径。
- 数据库已存在：跳过首启，直接恢复上次本地状态。
- 数据库密钥不可用或迁移失败：转 J-13，不创建新库覆盖旧数据。

待确认：最小资料字段、目标算法或纯手动目标、能否完全跳过，见 `UXD-03`。

## 3. J-02 查看某日并手工记录餐食

**目标**：飞行模式下完成从查找食物到保存日记的完整闭环。

正常路径：

1. 每日日记 → 选择日期或保持今天 → 选择餐次或新增餐食。
2. 新增任务层 → “搜索本地食物”。
3. 输入名称 → 同时检索已安装数据包与用户食品，清楚标注来源。
4. 选择食品 → 选择份量/单位 → 进入统一“检查并保存”。
5. 检查餐次、日期、份量、能量、P/C/F、纤维、糖、钠及缺失字段。
6. 保存 → 生成不可变营养快照 → 返回所选日期并更新汇总。

分支与失败：

- 无搜索结果：提供“创建用户食品”，不能自动发起在线搜索。
- 营养字段缺失：显示“未提供”，允许保存；不能替换为 `0`。
- 液体只有毫升但没有密度：不自动按 `1 ml = 1 g` 换算，要求选择已有体积营养基准或补充资料。
- 保存验证失败：保留表单输入并聚焦到第一个可修正字段。
- 数据库写入失败：保留草稿，给出重试与导出诊断信息的本地路径；不得记录敏感内容到日志。

完成条件：日记详情显示来源和保存时营养快照；后续数据包更新不改变该记录。

## 4. J-03 扫描条码记录包装食品

**目标**：只使用本地数据进行条码查找，并提供可信的未命中路径。

正常路径：

1. 新增餐食 → 扫描条码。
2. [相机权限未决定] 先解释本次需要相机扫描 → 用户继续后请求系统权限。
3. 扫描并本地标准化 GTIN → 查询用户食品和已安装数据包。
4. [精确命中] 显示商品名、来源、营养完整性和条码 → 选择份量 → 统一检查并保存。

分支与失败：

- 相机拒绝/受限：提供“输入条码”“搜索食物”“创建用户食品”和系统设置入口。
- 无法识别：允许重新扫描或输入数字，不把模糊识别当作命中。
- 条码未命中：明确为“本地食物库未找到”，提供手工建档、拍摄营养标签后手工录入，以及用户主动选择 AI 标签解析。
- 命中但首版营养字段不完整：显示缺失项；用户可复制为用户食品并补充，不直接改写数据包源记录。
- 多个本地来源冲突：按来源和版本列出候选，不静默合并。

完成条件：保存的是用户确认的食品与营养快照；不承诺中国包装食品全覆盖。

## 5. J-04 用 AI 生成餐食草稿

**目标**：用户清楚知道什么内容将发送到哪里，并始终保有最终决定权。

适用输入：餐食照片、相册照片、营养标签照片、自然语言描述。所有输入走同一个安全状态机，解析模板可不同。

正常路径：

1. 选择 AI 输入方式。
2. [需要媒体权限时] 在任务触发点解释用途并请求；文字不请求媒体权限。
3. 在设备内准备输入：裁剪/压缩图片、移除 EXIF；原图保留策略待 `UXD-06` 决策。
4. [首次使用] 显示 AI 数据边界说明。
5. 用本地版本化 Provider policy profile 核对 origin、model 与载荷类型；D-053 未接受或状态为 `DENY/UNKNOWN/EXPIRED` 时停在本地并说明原因，不读取 key、不组装请求体。
6. 每次发送前预览：输入缩略图或完整文本、将发送的数据类型、目标 host、model 和 policy 证据版本；API key 不显示也不进入载荷预览。该统一流程是 G3 推荐，D-014 已明确要求营养标签照片如此处理；其他 AI 输入是否同样使用独立预览页见 `UXD-13`。
7. 用户明确确认 → 唯一 `AITransport` 发起 HTTPS 请求；提供取消。
8. 响应先进入隔离解析和本地范围校验 → 形成 `AIDraft`。
9. 统一“检查并保存” → 用户逐项修改、删除或补充 → 明确保存。
10. 只有确认后的结构化内容生成营养快照和日记记录。

不得跨越的边界：

- 不在启动、拍照、选图或输入文字时自动发送。
- 不自动附加完整健康历史；任何洞察所需的数据范围必须由用户在当次任务中选择或检查，是否进入独立逐次预览页按 `UXD-13` / D-033。
- 不让 AI 覆盖有来源的数据包值；仅作为候选或用户明确选择的替代。
- 不把 AI 风险、益处、评分或建议写成医疗结论。

失败与恢复：

| 状态 | 用户看到什么 | 可执行恢复 | 数据结果 |
| --- | --- | --- | --- |
| 未配置 AI | “尚未配置 AI” | 配置；改用手工录入 | 输入草稿保留，本地库零写入 |
| Base URL 非 HTTPS | “仅支持 HTTPS 地址” | 修改地址 | 不发请求 |
| Keychain 凭据不可用 | “无法读取 API 凭据” | 重新输入 key；手工录入 | 不回显旧 key，不发请求 |
| Provider 用途未知、不相容或证据过期 | 显示 Provider、载荷类别、`UNKNOWN/DENY/EXPIRED` 和需复核的证据 | 返回修改；改用手工录入 | 不读取 key，不生成 Authorization/请求体，网络与业务库零写入 |
| 无网络 / 超时 | “未收到 AI 响应” | 重试；手工录入 | 草稿保留，日记零写入 |
| 401/403 | “AI 配置未通过验证” | 检查地址、model、key | 不暴露服务端响应中的敏感信息 |
| 429 / 限流 | “AI 服务暂时限制请求” | 稍后重试；手工录入 | 草稿保留 |
| 响应格式错误 | “AI 返回内容无法使用” | 查看安全摘要；手工录入 | 原始响应不进入业务数据 |
| 发送前取消 | “未发送，草稿已保留” | 继续编辑；退出 | 未创建网络请求，业务库零写入 |
| 发送中取消 | “已停止等待。内容可能已发送到 AI 服务，无法从本机撤回” | 继续编辑；退出 | 终止或忽略本地请求，候选和业务库零写入；不宣称 Provider 已删除载荷 |

## 6. J-05 修改、移动或删除食物记录

证据说明：公开资料未直接证明完整 CRUD；本旅程作为 `Nuttie-required` 的日记闭环，不标为竞品已确认。

正常路径：

1. 日记 → 打开记录详情。
2. 编辑 → 修改份量、单位、日期或餐次 → 预览对当日汇总的影响 → 保存新快照/修订信息。
3. 移动 → 选择目标日期与餐次 → 确认 → 原子更新两个日期的汇总。
4. 删除 → 显示食品、日期、餐次和影响范围 → 确认 → 删除记录并更新汇总。

约束：

- 食品数据包更新不替换历史快照。
- 删除和移动失败时原记录仍可见且状态不变。
- 撤销窗口、修订历史和批量操作是否提供待 Owner 决策，当前不作承诺。

## 7. J-06 记录饮水、运动和体重

正常路径：

1. 从日记新增任务或对应趋势域选择记录类型。
2. 输入数值、单位和时间；运动可输入类型、时长与消耗估算。
3. 检查并保存 → 当日摘要和趋势更新。

边界：

- 首版纯手工，不显示 HealthKit 开关、授权页、自动步数或待接入占位。
- 消耗热量的计算来源要可见；用户输入与公式估算不得混为“测量值”。
- 非法数值、极端值和单位变更需要内联校验，但不得用羞辱性语言。
- 快捷饮水量、运动类型和体重记录精度尚待确认。

## 8. J-07 查看趋势并可选请求 AI 指导

本地路径：

1. 打开身体与趋势 → 选择已支持的时间范围。
2. 查看体重、摄入、消耗、饮水、运动与营养聚合。
3. 每个图表同时提供文字摘要、数据范围和缺失天数说明。
4. 点选数据点可查看原始日记，修订后聚合重算。

AI 分支：

1. 用户选择“生成分析”“生成食谱”或“生成饮食方案”。
2. 选择/检查本次将发送的数据范围；默认不包含未明确列出的健康资料。
3. 按 J-04 展示 host 与发送内容并确认；是否使用独立逐次预览页由 `UXD-13` 决定。
4. AI 输出作为带生成时间、model 和免责声明的参考草稿展示。
5. AI 输出不能自动改变目标、创建餐食或覆盖本地趋势；任何转入日记的内容重新走统一确认。

失败：本地趋势持续可用；AI 错误仅显示在 AI 区域，不用全屏网络错误遮挡本地内容。

## 9. J-08 设置本地提醒

正常路径：

1. 提醒 → 新建规则 → 选择类型、时间和重复方式。
2. [通知权限未决定] 先保存规则草稿并说明系统通知用途 → 用户继续后请求权限。
3. [已授权] 安排本地通知 → 显示规则与系统状态。

分支：

- 拒绝/受限：规则保留为“未安排”，提供系统设置入口；应用其他功能照常可用。
- Focus 或系统延迟：文案说明“通知可能因系统设置延迟或不显示”，不承诺准点唤醒。
- 系统授权被撤销：下次进入提醒域时刷新状态，明确哪些规则未安排。
- 后台 JS 不执行：提醒调度不依赖后台 JavaScript 定时任务。

## 10. J-09 配置或移除个人 AI 凭据

配置路径：

1. 设置 → AI 配置 → 输入 HTTPS Base URL、model 和 key。
2. 本地校验 URL：只允许 HTTPS；规范化并展示实际 host。
3. 保存：Base URL/model 存本地配置；key 存 `ThisDeviceOnly` Keychain，不写数据库、日志或备份。
4. 用户可主动“测试连接”；测试也显示目标 host，并通过 `AITransport`。
5. 测试结果只说明连接/鉴权/模型可用性，不把完整服务端错误或 key 写日志。

移除路径：

1. 选择“移除 AI 凭据” → 说明 AI 功能将不可用、本地记录不受影响。
2. 确认 → 清除 Keychain key 与相关非敏感连接状态。

Keychain 失效时：将配置标为“需要重新输入”，不能假装仍可用，也不能自动降级到共享 key。

## 11. J-10 导入签名食品数据包

正常路径：

1. 食品资料 → 导入数据包 → 打开系统 Files 选择器。
2. 选择文件后在隔离区读取 manifest。
3. 校验 schemaVersion、sourceVersion、来源、许可证、SHA-256、签名、空间需求与兼容性。
4. 展示导入摘要：来源、版本、记录数、许可、将替换/新增的范围。
5. 用户确认 → 在临时区完成导入 → 原子切换到新数据包。
6. 记录导入结果；历史日记营养快照不变。

失败：

- 签名、哈希或 manifest 错误：拒绝导入并说明具体类别，不提供“强制继续”。
- 许可证缺失：拒绝导入；提供查看要求，不静默接受。
- schema 太新/太旧：保持当前数据包，说明所需 App 版本。
- 空间不足：显示所需与可用空间，允许取消和清理本地非必要媒体（若媒体保留功能已批准）。
- 导入中断：临时文件清理，当前包保持可用。

## 12. J-11 导出或导入加密个人备份

### 12.1 导出

1. 数据管理 → 导出加密备份。
2. 展示备份范围：日记、档案、目标、用户食品、提醒和配置；明确不包含 API key 与数据库密钥。
3. 设置并确认备份口令；说明应用无服务器，无法找回忘记的口令。
4. 本地生成加密归档并清理明文临时文件。
5. 调用系统 Files 保存；明确保存位置由 iOS 和已安装的文件提供方决定，可能包括 iCloud 或第三方位置。
6. 显示文件名、生成时间、版本和成功状态，不保留口令。

### 12.2 导入

1. 数据管理或首启恢复 → 系统 Files 选择备份。
2. 在隔离区检查容器、版本和完整性 → 输入口令 → 解密与校验。
3. 展示备份时间、版本、记录范围和冲突方式。
4. 用户明确确认 → 执行恢复；完成后重新打开数据库并核验关键计数。

不变量：

- 错误口令、损坏文件、版本不兼容、媒体缺失或空间不足时，当前数据库和 Keychain 不变。
- 恢复是替换、合并还是可选两种模式，以及是否先建立设备内恢复点，属于 `UXD-07`。
- Files 选择器可能访问云端位置，因此只能承诺“Nuttie 不主动上传”，不能承诺导出文件物理上永不进入云端。

## 13. J-12 删除凭据、记录或全部数据

| 删除范围 | 确认内容 | 完成结果 |
| --- | --- | --- |
| 单条记录 | 食品/类型、日期、影响的汇总 | 记录删除，聚合重算，其他数据不变 |
| 用户食品 | 是否仍被历史记录引用 | 食品库条目删除；历史快照仍可阅读 |
| AI 凭据 | AI 将不可用，本地功能不受影响 | Keychain key 和连接状态删除 |
| 全部本地数据 | 数据库、媒体、临时文件、Keychain、App Group 最小快照和提醒 | 回到无数据首启；外部 Files 备份不受影响 |

要求：全量清除使用明确范围和高风险确认；执行中断后必须能判定状态，不能留下应用误以为“已清除”的敏感数据。具体确认方式见 `UXD-08`。

## 14. J-13 数据库解锁或迁移失败

1. 启动 → 无法从 Keychain 获取数据库密钥、SQLCipher 解锁失败或 migration 失败。
2. 进入只读恢复界面，不自动新建空数据库覆盖原文件。
3. 提供：重试解锁、从加密备份恢复、查看非敏感错误代码、返回稍后处理。
4. 只有用户明确选择且通过高风险确认后，才可清除本地数据并重新开始。

错误界面不得显示 key、数据库内容、AI 输入、文件完整路径中的隐私信息或可还原敏感内容的堆栈。

## 15. 延期旅程

HealthKit、步数自动读取、Widget 和 Live Activity 不进入首版体验。第二阶段如启动，必须新增 Owner 决策、权限说明、部分授权/撤销流程、App Group 数据最小化、数据过期状态和真机验收；不得直接复用首版手工记录流程并宣称系统同步成立。
