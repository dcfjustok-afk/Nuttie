# 完整逻辑信息架构

状态：`DRAFT_FOR_REVIEW`  
目的：定义内容、任务和对象的归属，不决定具体导航控件、导航库或视觉样式。

## 1. 架构规则

1. “完整”指 D-001 口径下的 24 类、66 项公开证据均有去向；不表示未知的会员或真机细节已被确认。
2. 账号、会员、云同步、广告和遥测不复制到 Nuttie；相关用户目标分别由本地档案、加密备份和设备内数据权利替代。
3. 食物记录的所有入口最终进入同一个“检查并保存”对象，避免 AI 结果绕过人工确认。
4. AI 能力不占据本地核心任务的必经路径。AI 未配置或失败时，逻辑结构不坍塌。
5. 食品数据包、备份与业务记录分区呈现，避免把“导入食品资料”误解为“恢复个人日记”。
6. HealthKit 首版不出现；它只保留为第二阶段研究节点，不在首版请求权限或展示不可用入口。

## 2. 领域对象

| 对象 | 内容 | 关键关系与约束 |
| --- | --- | --- |
| 本地档案 `LocalProfile` | 昵称（可选）、基础资料、单位、目标偏好 | 不对应服务器账号；一台设备首版是否支持多个档案待决策 |
| 目标方案 `GoalPlan` | 每日能量、蛋白质、碳水、脂肪及适用日期 | 变更不回写历史；算法或手动设置方式待决策 |
| 每日日记 `DayLog` | 日期、摄入、消耗、剩余、营养汇总 | 聚合餐食、饮水、运动；跨时区和日界线规则需 QA 追踪 |
| 餐次 `Meal` | 早餐、午餐、晚餐、零食或候选自定义餐次 | 默认餐次结构属于待决策项；记录可移动餐次 |
| 食物记录 `FoodEntry` | 食物、份量、单位、餐次、时间、来源 | 保存不可变营养快照；支持编辑和删除 |
| 营养快照 `NutritionSnapshot` | 能量、P/C/F、纤维、糖、钠、缺失状态、来源和版本 | D-013 首版字段；`0` 与缺失严格分离 |
| 食品 `FoodItem` | 数据包食品或用户自建食品、别名、条码 | 官方源内容和用户内容可辨；用户覆盖不改写原始源 |
| 条码候选 `BarcodeCandidate` | 标准化 GTIN、匹配结果和来源 | 仅查本地；未命中不是网络错误 |
| AI 草稿 `AIDraft` | 待发送输入、目标 host、解析候选、原始响应摘要 | 所有请求须由用户主动发起；营养标签照片按 D-014 逐次预览，其他载荷按 `UXD-13` / D-033；未经检查不得生成业务记录 |
| 身体记录 `BodyRecord` | 体重及记录时间 | HealthKit 首版不参与；单位切换不丢原值 |
| 饮水记录 `WaterEntry` | 容量、时间 | 纯本地；默认快捷量待决策 |
| 运动记录 `ExerciseEntry` | 类型、时长、消耗估算、时间 | 首版手工；步数与 HealthKit 留待二阶段 |
| 提醒规则 `ReminderRule` | 类型、时间、重复、启用状态 | 映射本地通知；系统可能延迟或抑制 |
| 洞察快照 `InsightSnapshot` | 时间范围、聚合值、生成来源 | 本地统计与 AI 建议必须分区标识 |
| 食谱或方案 `GuidanceDraft` | AI 生成食谱、饮食方案、免责声明 | 是可删除的参考内容，不自动改变目标或日记 |
| 食品数据包 `FoodDataPackage` | 来源、许可、版本、schema、签名和校验值 | 先验证后原子切换；与个人备份分离 |
| 加密备份 `EncryptedBackup` | 业务记录、用户食品、配置及可选媒体清单 | 不含 API key 与数据库密钥；经 Files 导入导出 |

## 5. 公开证据缺口的 IA 处理

公开缺口不能统一做成“敬请期待”占位。按其对 Nuttie 的价值分为三种：

| 处理 | 缺口类别 | IA 表现 |
| --- | --- | --- |
| 仅研究台账，不进入 UI | 会员额度/价格/广告、账号绑定、平台扩展、知识/成功故事是否为模块 | 没有占位、禁用入口或“竞品同款”文案 |
| 作为 Nuttie 必要闭环重新立项 | 食物搜索与自建、日记编辑/删除/移动、AI 纠错、备份导入导出 | 进入逻辑 IA，但标记 `Nuttie-required`；验收基于 Nuttie 目标，不冒充竞品事实 |
| 能力入 IA，细节另行决策 | 目标问卷和算法、条码覆盖/OCR、饮水运动步数、提醒规则、统计范围 | 只承认能力类别；默认值、入口、算法和规则提交 Owner 决策 |

九组缺口逐组处理如下：

| Gap ID | 公开资料缺口 | G3 处理 | 用户可见边界 |
| --- | --- | --- | --- |
| EG-01 | 引导流程、目标字段和算法 | 本地档案与目标保留逻辑位置；具体字段/算法走 `UXD-03` | 不复制未知问卷，不把估算目标写成医学建议 |
| EG-02 | 食物库、搜索、自建、最近/收藏和日记高级操作 | 搜索、自建、编辑/删除/移动按 `Nuttie-required` 建立闭环；最近/收藏见 `UXD-10` | 明确是 Nuttie 方案，不写“竞品同款” |
| EG-03 | AI 纠错、重试、免费/会员额度 | 人工纠错属于 AI 安全不变量；额度和付费规则不进入 Nuttie | BYOK Provider 的限流只表现为服务错误，不制造会员额度 UI |
| EG-04 | 中国条码覆盖、未命中路径、标签 OCR | 本地 GTIN 精确查询、未命中建档、可选 AI 标签解析 | 不显示覆盖率承诺；命中与营养完整率分开表达 |
| EG-05 | 饮水/运动/步数 UI 与 HealthKit 行为 | 首版保留手工饮水、运动、体重；HealthKit/自动步数隐藏 | 不显示未接入开关或授权占位 |
| EG-06 | 提醒类型、重复规则、统计范围、筛选和导出 | 本地提醒与已证实 7 天趋势进入 IA；默认规则和更多范围另决策 | 不承诺系统准点通知；不把更多范围写成竞品事实 |
| EG-07 | 竞品备份、导出和同步细节 | 加密 Files 备份作为 `Nuttie-required` 本地替代 | 明确不是云同步；Files 最终位置由用户和 iOS 决定 |
| EG-08 | 游客限制、订阅门槛、恢复购买、广告冲突 | 无账号完整本地使用；会员、IAP 和广告不进入 UI | 不保留灰色付费入口或“永久免费”运营承诺 |
| EG-09 | iPad/其他语言、Android 分享/支付等平台扩展 | 首版只按 D-011/D-016 做 iOS 17+ 简中；其他平台能力留规划 | 不因竞品元数据自动承诺 iPad、三语或 Android 能力 |

## 6. 不在首版显示的节点

- HealthKit、系统步数、Widget、Live Activity：尚未有首版 Owner 决策或已由 D-007 延期。
- 会员、购买恢复、账号登录、云同步、广告、社交分享：被本地边界明确移除。
- 公开资料未证实的“成功故事/健康知识内容流”：仅研究项。
- 无法工作的灰色 AI 入口：AI 未配置时可展示有明确“配置”与“改用手工”动作的任务入口，但不得形成死路。

## 7. 导航外壳边界

首版导航外壳已由 D-038 接受 UXD-01=A；添加餐食首层已由 D-039 接受 UXD-02=A，并在 [D-039 PX-4 设计基线](d039-px4-design-baseline.md) 冻结本地搜索/最近优先、扫描与 AI 并列的层级。洞察/AI 的全局逻辑位置 UXD-04 仍须独立决定。无论选择哪种全局 AI 位置，上述对象、能力去向与降级路径保持不变。
